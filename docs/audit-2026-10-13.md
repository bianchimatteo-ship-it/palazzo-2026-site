## 7. Pubblicazione, sicurezza, salvataggi

- **Build**: il sito è statico, non c'è una fase di compilazione; il «build» è `npm run version:build` (timbro) e `check:assets` (contenuto pubblicato calcolato in locale: moduli raggiungibili da `src/main.js`, fogli di stile, dati reali, loghi, icone, service worker; esclusi Worker, migrazioni, script, documenti, copia mobile; limiti Workers rispettati; binding del Worker dichiarati; nessun segreto nei file tracciati).
- **Sicurezza**: CORS non aperto; `_headers` e `nosniff`; `no-store` sull'API; errori interni senza dettagli. **Non applicata** una Content-Security-Policy: gli stili inline e gli attributi `style` dell'interfaccia la romperebbero, serve un lavoro dedicato.
- **Salvataggi**: locali verificati (`check:saves`, round-trip, versione futura, backup); online con revisione obbligatoria e CAS (`check:accounts` contro un D1 simulato con `node:sqlite`). Nessun salvataggio, slot o dato storico è stato toccato o migrato.
- **Deploy: NON eseguito.** Credenziali Cloudflare e raggiungibilità di `*.workers.dev` non verificate da questa sandbox; nessuna pubblicazione in produzione senza verificare configurazione e destinazione. Per pubblicare: `npm run cf:deploy`, poi `npm run check:published-site -- <url>`; verificare che Cloudflare applichi `_headers` agli asset serviti dal Worker, che il dominio `workers.dev` sia in `ALLOWED_ORIGINS` e l'URL predefinito di GitHub Pages in `check-published-site`.
